# DSH Ecosystem Artifact Taxonomy — Summary

The DeepSeek Harness (DSH) ecosystem centers on a **Cordis-based plugin architecture** where "everything is a plugin." Beyond the ~95 core `@deepseek-ai/dsh-*` framework packages (seams, services, UI primitives, tools, profiles) published on npm, the community has produced **10,000+ Cordis plugins** distributed primarily through **four competing catalogs** (dshmarket.com: 10,119; awesome-dsh-plugin.com: 10,365; dshget.com: 11,646; OMDSH Hub: 889 curated) plus a GitHub topic index (499 repos). These plugins span **28 human-curated categories** including UI enhancements (2,000+), tools & capabilities (1,300+), models & providers (500+), themes/skins (376), skills (360), memory (400+), workflow/automation (600+), IM connectors (Feishu/WeChat/DingTalk/QQ/Slack/Telegram/Discord/WhatsApp via OneBot/NapCat), MCP server bridges (23+ in OMDSH Hub), and desktop-specific integrations. **Six distinct desktop applications** (Dataelem DSH Desktop, dsh-tauri, Anywhere Labs, RyensX DSH App, MochiNek0, Local DSH) ship native installers (Windows .exe, macOS .dmg) with bundled plugin presets and local model support (llama.cpp/GGUF). A **format-1 machine-readable plugin market index** (`index.json` served via jsdelivr CDN from the `dsh-plugin-catalog` npm package) powers the in-app Discover tab and `plugin_market` agent tool, while **three additional catalog feeds** (hrhgit v2, OMDSH Hub workshop v0.4, awesome-dsh-plugin Atom) provide structured discovery with differing taxonomies (OMDSH's `kind`: extension/mcp/skill/ui/toolkit/adapter/channel is the most technically granular). Installation uses `dsh plugin add <spec>` resolving from GitHub, npm, local paths, or the market index; hot-reload and failure isolation are declared per-plugin in OMDSH Hub but largely unverified for community plugins. Key gaps: the format-1 index could not be fetched (CDN returns 0 bytes), the awesome-dsh-plugin catalog.json exceeds tool size limits, no canonical plugin category taxonomy exists across catalogs, desktop app update mechanisms and bundled plugin manifests are undocumented, and MCP server distribution remains fragmented across npm, GitHub, and toybox collections.
