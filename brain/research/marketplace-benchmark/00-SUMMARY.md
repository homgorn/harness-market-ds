# Marketplace Benchmark Summary

Benchmarking 20 plugin/agent marketplaces reveals five dominant patterns a new DSH catalog should adopt: (1) **Faceted, programmatic-SEO URL structures** (category → subcategory → tag → capability) with self-referencing canonicals and static paths, used by npm, WordPress.org, and Glama to capture long-tail search at scale; (2) **Tiered trust signals** — verified publisher badges (VS Code, JetBrains, Figma), malware scanning (Chrome Web Store, npm), permission manifests (MCP registries), and quality/maintenance grades (Glama, mcp.so) — which correlate with higher install-to-view ratios; (3) **15% platform commission** as the de facto standard for paid transactions (JetBrains, Figma, historical Chrome Web Store), with freemium + external licensing as the dominant OSS-friendly model (VS Code, Obsidian, WordPress.org); (4) **Taxonomy depth of 3–4 levels** (e.g., Glama's category → capability → hosting type → language) balancing discovery vs. cognitive load, with keyword tags as a flexible overlay; (5) **Author/profile pages as SEO pillars** — npm and Glama expose full publisher portfolios with package counts, creating compounding internal link equity. For a free OSS catalog, the viable monetization path is **zero platform fees + optional sponsorship badges + paid placement/advertising** (mcp.so, Glama "Advertise" slots), avoiding the revenue-share model that requires payment infrastructure and alienates volunteer maintainers. The largest gap: no marketplace currently unifies "plugins" and "agents/bots" in a single taxonomy with cross-install tracking — an opportunity for DSH.
