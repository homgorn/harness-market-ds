# DSH Ecosystem Marketplace — Research Summary

This research analyzed nine multi-entity marketplaces (VS Code Marketplace, Chrome Web Store, npm, Figma Community, Hugging Face Spaces, Docker Hub, Homebrew, OBS Studio, MCP Registry) to derive design-grade patterns for a unified catalog spanning plugins, SaaS products, hosted sites, services, bots, themes, skills, and desktop apps. **All marketplaces converge on a shared-base-schema + type-specific-extensions pattern** (measured: 9/9), avoiding lowest-common-denominator flattening. Global facets (publisher, rating, install count, price, recency, tags) apply across types; type-specific facets (runtime/SDK, platform/arch, permissions/capabilities, hardware tier, language/framework) live in typed extensions. Trust signals layer platform-level guarantees (malware scanning, publisher verification badges, supply-chain provenance) atop type-specific signals (permission manifests, capability declarations, hardware requirements). Related-item computation blends explicit tags/categories, dependency/dependent graphs, and co-install/co-view collaborative signals where telemetry exists. SEO-safe faceted URLs use query parameters with canonical tags pointing to unfiltered parent pages, not path segments, to prevent duplicate-content explosion. Citation-worthy pages require Schema.org Product/SoftwareApplication + type-specific extensions + JSON-LD @id/entity linking + sameAs to authoritative sources (Wikidata, GitHub, official sites). Key gap: no public documentation exists for collaborative-filtering weightings in any marketplace; all related-item algorithms are inferred from UI behavior.
